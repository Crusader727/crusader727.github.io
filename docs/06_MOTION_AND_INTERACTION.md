# Motion & Interaction

## Назначение

Motion — не украшение интерфейса.

Анимации помогают пользователю понимать происходящее, создают ощущение живого продукта и подчеркивают премиальность интерфейса.

Каждая анимация должна иметь практический смысл.

---

# Основные принципы

Анимации должны быть:

- плавными;
- естественными;
- ненавязчивыми;
- быстрыми;
- последовательными.

Интерфейс не должен отвлекать пользователя.

---

# Общие правила

- Использовать easing вместо линейных анимаций.
- Избегать резких изменений положения элементов.
- Не использовать бесконечные активные анимации без причины.
- Предпочитать transform и opacity вместо изменения размеров и координат.
- Все анимации должны работать при 60 FPS.

---

# Длительность

Micro

100–150 ms

Small

180–250 ms

Medium

300–450 ms

Large

500–700 ms

Hero

800–1200 ms

---

# Hover

Hover должен ощущаться физическим.

Используются:

- небольшое увеличение;
- изменение глубины;
- усиление свечения;
- изменение прозрачности стекла;
- мягкое поднятие элемента.

Запрещается использовать резкую смену цвета.

---

# Active

При нажатии элемент слегка уменьшается.

Создается ощущение физического взаимодействия.

---

# Focus

Focus строится на мягком свечении.

Без ярких рамок.

---

# Появление элементов

Элементы не появляются мгновенно.

Используются:

- Fade;
- Translate;
- Scale;
- Blur.

Все появления должны быть плавными.

---

# Исчезновение

Обратный принцип появления.

Без резких исчезновений.

---

# Скролл

Скролл естественный.

Без искусственных задержек.

Без sticky-сцен.

Без сложных scroll-хаков.

Каждая секция живет самостоятельно.

---

# Параллакс

Используется минимально.

Только для:

- света;
- фоновых объектов;
- декоративных элементов;
- Identity Object.

Контент не должен "плавать".

---

# Курсор

Курсор взаимодействует с интерфейсом.

Поддерживаются:

- магнитные кнопки;
- легкий 3D-наклон карточек;
- локальное свечение;
- реакция стеклянных поверхностей.

Эффекты должны быть деликатными.

---

# Glass

Стеклянные элементы постоянно "живут".

Допускаются:

- медленное дыхание;
- плавное изменение бликов;
- легкое изменение прозрачности;
- внутреннее свечение.

---

# Hero

Главный экран может использовать более выразительные анимации.

Допускаются:

- плавное вращение Identity Object;
- движение световых сфер;
- постепенное появление типографики;
- последовательное раскрытие элементов.

---

# Dashboard

Dashboard использует минимальное количество анимаций.

Основной акцент — скорость работы.

Анимации помогают восприятию информации, а не создают шоу.

---

# Загрузка

Используются Skeleton Loader.

Контент постепенно проявляется.

Избегать глобальных прелоадеров.

---

# Empty State

Пустые состояния могут содержать:

- небольшую анимацию;
- иллюстрацию;
- рекомендацию;
- быстрые действия.

---

# Page Transition

Переход между страницами должен восприниматься как переход между рабочими пространствами, а не как загрузка нового сайта.

Используются:

- Fade;
- Scale;
- Shared Element Transition (при возможности);
- мягкое изменение глубины.

---

# Производительность

Приоритет всегда отдается производительности.

Любая анимация может быть упрощена, если это необходимо для сохранения плавности интерфейса.

---

# Главный принцип

Пользователь должен замечать не сами анимации, а качество продукта.

Если анимация привлекает к себе больше внимания, чем контент, значит она выполнена неправильно.
