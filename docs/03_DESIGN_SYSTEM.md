# Resident Card 2.0

# Design System

Version: 2.0

---

# Назначение

Данный документ описывает единый визуальный язык Resident Card 2.0.

Любой новый экран обязан соответствовать данной дизайн-системе.

Не допускается создание компонентов, нарушающих описанные правила.

Главная цель дизайн-системы — создать ощущение единого цифрового продукта.

---

# Главные принципы

Дизайн Resident Card строится на пяти основных принципах.

• Пространство

• Свет

• Материал

• Типографика

• Движение

Все остальные решения являются следствием этих пяти принципов.

---

# Визуальная философия

Интерфейс должен выглядеть дорого.

Не ярко.

Не необычно.

Именно дорого.

Пользователь должен ощущать качество продукта даже без взаимодействия с ним.

Интерфейс не должен пытаться привлечь внимание.

Он должен вызывать доверие.

---

# Пространство

Свободное пространство — основной строительный материал интерфейса.

Запрещается пытаться заполнить экран полностью.

Каждый экран должен "дышать".

Если существует выбор между:

• добавить блок

или

• оставить пустое пространство

в большинстве случаев необходимо оставить пространство.

# Материалы

Resident Card использует три типа поверхностей.

---

## Solid

Обычные поверхности.

Используются редко.

Главным образом для текста.

---

## Glass

Основной материал проекта.

Используется практически везде.

Параметры:

backdrop-filter

20–40px

opacity

35–60%

тонкая светлая рамка

внутренний блик

мягкая тень

---

## Light

Используется только как источник атмосферы.

Никогда не используется как декоративный элемент.

Большие световые пятна.

Размытые градиенты.

Объемное свечение.

---

# Правила типографики

Минимум текста.

Крупные заголовки.

Максимальный контраст размеров.

Большие межстрочные интервалы.

Минимальная ширина текстовых блоков.

---

# Иконки

Используются простые контурные иконки.

Толщина линий одинаковая.

Размеры:

20

24

28

32

40

Иконки не являются основным визуальным элементом.

---

# Кнопки

Кнопки большие.

Стеклянные.

Мягкие.

Используют эффект света.

Hover строится на глубине, а не на смене цвета.

При наведении:

подъем

увеличение

световой блик

усиление свечения

---

# Карточки

Карточки являются основным компонентом продукта.

Основные правила.

Большие радиусы.

Большие внутренние отступы.

Стеклянная поверхность.

Минимум текста.

Один главный акцент.

Не более одного основного действия.

---

# Формы

Формы максимально упрощаются.

Каждое поле имеет большое количество воздуха.

Запрещаются длинные вертикальные формы.

При возможности используются пошаговые сценарии.

---

# Таблицы

По возможности полностью исключаются.

Если таблицу можно заменить карточками —

заменяется.

Если нельзя —

используется современный Data Grid.

---

# Иллюстрации

Используются абстрактные формы.

Свет.

Стекло.

Объем.

Не используются стоковые изображения.

---

# Empty States

Каждое пустое состояние имеет собственную композицию.

Не допускается простой текст:

"Нет данных"

Используются:

иллюстрации

анимации

рекомендации

быстрые действия

---

# Загрузка

Используются Skeleton Loader.

Запрещаются классические спиннеры, если их можно избежать.

Интерфейс должен постепенно проявляться.

---

# Состояния компонентов

Каждый компонент обязан иметь:

Default

Hover

Active

Focus

Disabled

Loading

Success

Error

Все состояния проектируются заранее.

---

# Принцип повторного использования

Любой компонент создается один раз.

После этого используется во всем проекте.

Запрещается создавать новые варианты компонента без необходимости.
