# Resident Card 2.0

# Information Architecture

Version: 2.0

---

# Назначение документа

Данный документ описывает полную архитектуру продукта Resident Card 2.0.

Здесь определяется:

- структура продукта;
- основные разделы;
- пользовательские сценарии;
- логика переходов;
- взаимосвязь между экранами;
- новая организация функционала.

Главный принцип — отказаться от логики отдельных страниц и перейти к логике единой цифровой экосистемы.

---

# Общая архитектура

Resident Card состоит из двух независимых уровней.

```

Landing Experience

↓

Авторизация

↓

Product Experience

```

Landing отвечает за первое впечатление.

Product Experience отвечает за ежедневное использование.

---

# Landing Experience

Landing не является маркетинговым сайтом.

Он представляет собой презентацию продукта.

Landing состоит из трех полноценных сцен.

```

Scene 01

Arrival

↓

Scene 02

Ecosystem

↓

Scene 03

Dashboard Reveal

```

После окончания Landing пользователь плавно переходит в продукт.

---

# Product Experience

После авторизации пользователь попадает на главный экран приложения.

Все остальные разделы являются продолжением этого пространства.

Навигация не должна создавать ощущение перехода между разными страницами.

---

# Новая структура продукта

```

Resident Card

│

├── Home

├── Cards

├── Benefits

├── Promotions

├── Services

├── Documents

├── Profile

├── Search

├── Notifications

└── Settings

```

---

# Home

Главная страница.

Является цифровым центром продукта.

Пользователь должен получать максимум полезной информации без необходимости переходить в другие разделы.

Главная показывает:

• статус карты

• активные льготы

• новые акции

• избранные сервисы

• документы

• быстрые действия

• рекомендации

Главная — это Dashboard.

Не список.

Не портал.

Именно современный Dashboard.

---

# Cards

Раздел полностью посвящен картам пользователя.

Возможности:

• цифровая карта

• физическая карта

• история использования

• управление картой

• перевыпуск

• QR

• NFC

• настройки

Если пользователь имеет несколько карт, переключение между ними происходит внутри одной сцены.

Никаких отдельных страниц.

---

Категории.

Поиск.

История использования.

# Promotions

Не список.

Практически App Store.

Большие баннеры.

Красивые карточки.

Категории.

Сезонные подборки.

Популярные предложения.

Локальные предложения.

историю использования

# Пользовательский путь

Новый пользователь проходит следующий сценарий.

```

Landing

↓

Авторизация

↓

Главная

↓

Изучение Dashboard

↓

Работа с сервисами

↓

Повторное использование

```

Пользователь никогда не должен чувствовать потерю контекста.

---

# Принцип объединения

Если несколько функций могут находиться на одном экране —

они объединяются.

Запрещается создавать отдельные страницы только ради одного действия.

---

# Принцип глубины

Каждый следующий уровень интерфейса раскрывает дополнительные возможности.

Основной экран остается максимально чистым.

Подробности появляются только при необходимости.

---

# Новые сущности продукта

Resident Card 2.0 вводит несколько новых концепций.

## Dashboard

Главная рабочая область пользователя.

---

## Command Palette

Быстрый доступ ко всем действиям продукта.

Вызывается горячей клавишей или кнопкой поиска.

---

## Quick Actions

Набор наиболее востребованных действий.

Например:

Показать QR

Открыть карту

Оплатить

Посмотреть льготы

Открыть документ

---

## Smart Recommendations

Система автоматически предлагает полезные сервисы.

На основании активности пользователя.

---

## Activity Timeline

История последних действий.

Без перегруженных логов.

В красивом визуальном формате.

---

# Архитектурный принцип

Мы больше не проектируем отдельные страницы.

Мы проектируем цифровые пространства.

Каждый раздел представляет собой самостоятельную рабочую область, внутри которой пользователь решает определенную задачу.

Все пространства используют единые правила построения интерфейса.
