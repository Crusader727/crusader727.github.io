# Product Experience

## Общая концепция

Resident Card — это единое цифровое пространство региона.

После авторизации пользователь не попадает на "главную страницу сайта".

Он попадает в свое личное цифровое пространство.

Все разделы являются частью единой экосистемы.

---

# Структура продукта

```
Dashboard

├── Cards
├── Benefits
├── Promotions
├── Services
├── Documents
├── Profile
├── Search
├── Notifications
└── Settings
```

Все разделы используют единую дизайн-систему и ощущаются как единый продукт.

---

# Dashboard

Dashboard — главный экран приложения.

Это центр всей экосистемы.

Пользователь должен иметь доступ ко всему самому важному без необходимости открывать дополнительные страницы.

Dashboard содержит:

- цифровую карту;
- активные льготы;
- персональные акции;
- быстрые действия;
- документы;
- историю активности;
- рекомендации;
- последние уведомления.

Главная задача Dashboard — дать ощущение контроля.

---

# Cards

Раздел управления картами.

Функции:

- просмотр карты;
- переключение между картами;
- QR-код;
- NFC;
- история операций;
- настройки карты;
- перевыпуск.

При наличии нескольких карт переключение происходит внутри одного пространства.

---

# Benefits

Каталог льгот.

Основные возможности:

- категории;
- поиск;
- фильтрация;
- персональные рекомендации;
- избранное;
- просмотр условий;
- история использования.

Информация представляется в виде крупных карточек.

---

# Promotions

Каталог предложений партнеров.

Раздел напоминает современный App Store.

Используются:

- большие баннеры;
- подборки;
- категории;
- рекомендации;
- избранное;
- персональные предложения.

---

# Services

Единая библиотека сервисов региона.

Каждый сервис содержит:

- описание;
- статус;
- быстрые действия;
- историю использования;
- связанные документы;
- необходимые льготы.

---

# Documents

Цифровой кошелек документов.

Документы отображаются в виде современных цифровых карточек.

Поддерживаются:

- просмотр;
- QR;
- реквизиты;
- экспорт;
- быстрый доступ.

---

# Profile

Цифровая идентичность пользователя.

Раздел включает:

- личные данные;
- уровень аккаунта;
- устройства;
- безопасность;
- историю активности;
- настройки.

---

# Search

Глобальный поиск по всему продукту.

Поиск работает одновременно по:

- льготам;
- акциям;
- документам;
- сервисам;
- настройкам;
- организациям.

Поиск должен быть доступен с любого экрана.

---

# Notifications

Единый центр уведомлений.

Все события автоматически группируются по категориям.

Поддерживаются:

- фильтрация;
- поиск;
- отметка прочитанным;
- закрепление важных уведомлений.

---

# Settings

Настройки делятся на логические категории.

- Аккаунт
- Безопасность
- Карты
- Интерфейс
- Уведомления
- Конфиденциальность

Настройки не должны перегружать пользователя.

---

# Принципы проектирования страниц

Любой раздел продукта должен:

- решать одну основную задачу;
- иметь понятную визуальную иерархию;
- использовать одинаковые компоненты;
- поддерживать единый язык анимаций;
- быть продолжением Dashboard.

---

# Что запрещено

- Таблицы без необходимости.
- Мелкие карточки.
- Перегруженные формы.
- Большие текстовые блоки.
- Длинные списки без поиска.
- Разные стили компонентов в разных разделах.

---

# Главная идея

Пользователь никогда не должен ощущать, что переходит между разными сервисами.

Он всегда остается внутри одного цифрового пространства.
