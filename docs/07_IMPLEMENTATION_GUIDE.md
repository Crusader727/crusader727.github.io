# Implementation Guide

## Цель

Определить единые правила разработки Resident Card 2.0.

Все решения должны соответствовать философии проекта, дизайн-системе и принципам Experience First.

---

# Технологический стек

Frontend:

- HTML5
- CSS3
- Vanilla JavaScript (ES6+)

Запрещается использовать:

- Bootstrap
- Tailwind CSS
- jQuery
- UI Kit'ы
- готовые шаблоны

Допускается использование небольших специализированных библиотек только при наличии веской причины (например, GSAP для сложных анимаций или Lenis для плавного скролла).

# HTML

Основные требования:

- семантическая разметка;
- минимальная вложенность;
- понятные class name;
- отсутствие инлайн-стилей;
- отсутствие инлайн-JS.

---

# CSS

Использовать:

- CSS Variables;
- Flexbox;
- CSS Grid;
- Clamp;
- Backdrop Filter;
- CSS Animations.

Не использовать:

- !important без необходимости;
- дублирование стилей;
- фиксированные размеры там, где возможна адаптивность.

---

# JavaScript

Использовать современный ES6+.

Основные принципы:

- модульность;
- читаемость;
- минимум глобальных переменных;
- разделение логики по файлам;
- комментарии только там, где это действительно необходимо.

---

# Компонентный подход

Любой повторяющийся элемент должен быть универсальным компонентом.

Примеры:

- Button
- Card
- Glass Panel
- Section
- Modal
- Input
- Navigation
- Badge
- Chip
- Dialog
- Notification

Не допускается создание одинаковых компонентов с разными реализациями.

---

# Адаптивность

Основные точки:

- Mobile
- Tablet
- Laptop
- Desktop
- Wide Screen

Интерфейс проектируется Desktop First.

Мобильная версия не является уменьшенной копией десктопа.

При необходимости допускается изменение композиции.

---

# Производительность

Приоритеты:

1. Плавность.
2. Скорость загрузки.
3. Минимум JavaScript.
4. CSS-анимации вместо JS.
5. Lazy Loading для тяжелого контента.
6. Оптимизация изображений.

Целевая производительность — стабильные 60 FPS.

---

# Accessibility

Минимальные требования:

- клавиатурная навигация;
- корректный focus;
- достаточный контраст текста;
- aria-атрибуты для интерактивных элементов;
- поддержка prefers-reduced-motion.

---

# Кодстайл

Код должен быть:

- простым;
- предсказуемым;
- масштабируемым;
- хорошо структурированным.

Главное правило:

Любой новый разработчик должен понять структуру проекта без дополнительных объяснений.

---

# Definition of Done

Работа считается завершенной, если:

- соответствует философии проекта;
- соответствует дизайн-системе;
- соответствует Motion System;
- имеет адаптивную версию;
- имеет все состояния компонентов;
- не содержит визуальных ошибок;
- обеспечивает плавную работу;
- готова к дальнейшему масштабированию.

---

# Финальный принцип

Resident Card 2.0 — это не набор веб-страниц.

Это единый цифровой продукт.

Любое новое решение должно улучшать пользовательский опыт, а не просто добавлять функциональность.
